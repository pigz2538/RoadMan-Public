# 安全、降级与数据边界

## 产品责任边界

RoadMan 是出发前和行程修改阶段的规划辅助系统，不接入 CAN 总线、车机控制、自动驾驶或驾驶辅助执行接口，不控制方向、制动、动力、充电或车门。实时导航、道路和气象主管部门公告、交通与景区运营方信息、车辆仪表及驾驶员判断始终具有最终优先级。规划结果和导出文件不得作为自动驾驶指令、应急处置结论或车辆性能承诺。

## 外部服务失败时的诚实降级

- 天气缺失：阶段附加 `WEATHER_DATA_DEGRADED`，继续使用基础风险模型，不把历史值写成逐时预报。
- 补能地点缺失：可生成沿路线的估算检查位置并附加 `ENERGY_STOP_ESTIMATED`；它是待确认点，不冒充营业中的充电站或加油站。
- 充电功率缺失：按车辆上限与 60kW 公共快充保守值的较小者估算，附加 `CHARGING_POWER_ESTIMATED`，并公开计算依据、补能量和预计时长。
- 真实道路 geometry 缺失：不把直线当作导航路线；前端只能绘制带降级说明的示意线。
- 班次、开放、票务和预约缺失：字段保持 `unknown` / `unavailable`，不生成虚构编号、价格或开放状态。

这些降级是非阻断信息时允许继续规划；若能量、时间或路线安全仍不可满足，则由校验器阻止交付。前端行程页和所有新生成的 Markdown/导出物都显示安全边界，阶段卡片继续保留逐项 warning。

## 数据收集与存储

当前版本是本地受控 Demo。系统收集用户主动输入的行程需求、车辆规划参数、对话与编辑状态、上传附件、规划版本、外部工具调用摘要及结果来源。默认不要求身份证、支付信息、车牌、精确家庭住址或持续位置轨迹；不要在提示词和附件中提交这些信息。API Key 只通过本机环境变量注入，不写入数据库、日志、导出物或仓库。

行程文档、消息和规划状态保存在 PostgreSQL；附件保存在 `UPLOAD_DIR`，数据库只保存安全文件名和元数据；Skill 调用审计只保存 adapter/provider、成功状态、延迟、错误码和来源摘要，不保存请求头或密钥。模型私有思维链不落库。

## 保留与删除

- 附件默认保留 30 天，由 `FILE_RETENTION_DAYS` 调整；定时任务只删除 `UPLOAD_DIR` 安全边界内的文件。
- 用户删除一条行程时，后端在同一数据操作中清理行程文档、消息/规划状态、保存版本、关联附件元数据、后台任务和该行程的 Skill 调用记录，并删除安全目录内的附件实体文件。
- 未关联具体行程的系统健康审计不随单条行程删除；当前 Demo 没有账户级长期画像或跨行程位置记忆。
- 当前是不可恢复的硬删除，前端在执行前明确二次确认。若未来改为公网多用户服务，必须在上线前补充账号鉴权、租户隔离、隐私告知、数据导出、授权撤回和数据主体请求流程。

## 演示建议

比赛 Demo 至少展示一次天气或补能 provider 中断：系统继续生成可阅读结果，同时显示降级原因、估算依据和出发前确认动作；再删除该测试行程，证明历史记录、版本和附件同步消失。不得把示例底图、模拟续航样本或估算补能位置描述为实时真实数据。
