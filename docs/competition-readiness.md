# GOAI 参赛能力与差距审计

本文按《GOAI 无界应用｜Boundless Agents 参赛手册》8.1–8.6 的要求清单，对当前仓库实现逐项核对。结论基于 `backend/`、`frontend/`、`deploy/`、`evaluation/` 的现有代码、接口、Docker 配置和验收脚本，不把尚未实现的能力写成已完成。已具备、部分具备、未具备都用状态标注明确区分。

## 1. 结论

RoadMan 是面向自驾与中短途旅行的多智能体行程工作台。用户用自然语言描述出行目标，系统经过语义提取、逐项澄清、后台 LangGraph 规划、SSE 渐进展示、PlanPatch 预览式编辑和五格式导出完成全闭环。Agent 能力、任务闭环、可演示性和外部工具调用都已有真实后端支撑。

相对 8.1–8.6 的总体状态：

- 应用闭环与 Agent 能力：已具备可演示基线。规划、复核、自动修复、编辑确认和多格式导出都有真实代码路径。
- 数据可追溯：主体已实现。`SourceRecord` 统一保存来源、URL 与抓取时间，但除 Open-Meteo 天气源外，多数来源未填许可证字段。
- 评测证据：已形成四层入口——12 条需求理解场景、12 条模拟传感器回放的续航误差基准、5 条生产规划安全/降级场景，以及新建→规划→校验→编辑→导出的完整旅程验收。结果写入机器可读 JSON；真实路测与云端完整旅程仍需在提交环境补运行证据。
- 安全边界：系统不接车辆控制，只有 IP 限流，默认单用户受控模式。只有计划开放公网写入时，登录与资源鉴权才升级为前置条件。

## 2. 目标用户、任务与 Agent 必要性

目标用户是需要规划自驾或中短途综合交通行程的个人、情侣和家庭。核心任务不是推荐几个景点，而是在日期、返程时限、天气、开放时间、交通方式、车辆续航、休息补能、餐饮住宿和个人偏好相互制约时，产出可执行且可修改的完整行程。

这类任务需要 Agent 的原因：

1. 自然语言里包含相对日期、隐含人数、舒适度、特殊事件和交通偏好，需要语义理解与追问。
2. 路线、班次、天气、地点、车型和公开资料来自不同系统，需要按上下文选择工具并统一结果。
3. 候选地点不能只按距离排序，需要结合来源、知名度、季节、天气、日期和用户偏好判断。
4. 路线、活动和三餐住宿相互影响，需要多轮复核与自动修复，而不是一次内容生成。
5. 用户修改必须先预览影响、确认后落库，并支持回滚与重新规划。

## 4. 任务闭环和可演示证据

完整链路如下：

1. `POST /api/v1/trips/preflight` 由需求提取智能体读取目标、日期、人数、偏好和交通方式。
2. 不确定项进入逐项澄清；用户确认前不启动正式规划。
3. `POST /api/v1/trips/{id}/planning/start` 创建异步 Job，Worker 执行 LangGraph。
4. 编排依次执行目的地研究、真实路线、跨城班次、地点候选、车辆、补能、天气、季节适配、日程与每日复核。
5. SSE 将工具开始/完成、阶段新增、活动新增和警告逐步推送到详情页。
6. 相邻阶段在同一接驳区域内会统一为同一逻辑站点；真实道路点列始终保留，不用直线冒充导航。
7. `verify_plan` 出现阻断项时进入 `repair_plan`，重新编排三餐、停留与接驳并再次复核，最多 4 轮；仍违反硬约束才请求用户调整。
8. 用户可用自然语言或地图选点创建 PlanPatch，先预览影响，再 apply/reject；已应用修改支持 rollback。
9. 仅状态为 completed 的行程可导出，历史行程直接从持久化状态恢复。

参赛 Demo 建议固定展示：

- 一个需要语义追问的周末跨城请求；
- 一次真实地图/天气/旅行信息工具调用及来源；
- 一次阶段不连续或日程冲突被 verify⇄repair 自动修复；
- 一次“替换景点/增加餐厅”的预览、确认和回滚；
- 一个完成后的图文导出与历史恢复；
- 一个 provider 不可用时的可解释降级。

| 数据/能力 | 用途 | 当前处理 | 提交前需要确认 |
| --- | --- | --- | --- |

| FlyAI / 飞猪 CLI | 交通、酒店、POI、旅行搜索 | `FLYAI_API_KEY` 注入；命令超时、解析与调用审计 | 结果展示、缓存与转授权边界 |
| OpenTripMap | 开放地点候选 | `OPENTRIPMAP_API_KEY` 注入；只作候选，保留来源 | ODbL/服务条款与导出署名要求 |

## 6. 按评分权重确定投入方向

| 评分维度 | 权重 | RoadMan 当前优势 | 最有效的提升 |
| --- | ---: | --- | --- |
| 行业场景价值 | 25% | 与“AI+汽车—长途出行规划”高度一致 | 用真实用户故事证明普通地图 App 无法同时处理车辆、同行人、补能、天气、吃住和返程约束 |
| Agent 能力与闭环 | 25% | 语义预检、多轮确认、LangGraph、工具调用、verify⇄repair、语义编辑 | Demo 展示“理解—研究—选择工具—生成—发现问题—自动修复—用户修改—重新验证” |
| 产品体验与 Demo | 20% | 渐进详情、地图、卡片、聊天修改、导出与历史 | 固定一条 4–6 分钟稳定演示路径，预先准备异常降级样例 |
| 技术实现深度 | 15% | 多适配器、异步队列、SSE、状态/版本、图文导出 | 用一张架构图说明状态流转，给出真实调用日志 |
| 安全合规可追溯 | 10% | 不控制车辆、来源记录、失败不伪造、人工确认 | 做一页简洁数据来源表、授权状态与风险边界 |

### 初赛优先

1. 先讲场景而不是罗列功能：目标用户定位为长途自驾、情侣/家庭和新能源车主。
2. 形成 500 字以内作品简介和 10–12 页方案，按“痛点—为什么需要 Agent—任务闭环—产品 Demo—技术架构—真实结果—数据边界—复用价值”组织。
3. 准备一个稳定主 Demo，必须展示工具调用、逐步成形、自动复核、补能/餐饮/住宿和一次自然语言修改。
4. 准备一个异常 Demo，展示可解释降级与自动修复。
5. 提供 8–12 个代表场景的评测，报告约束提取、路线闭环、三餐住宿、来源覆盖与自动修复结果。
6. 材料与 Demo 严格一致，未实现能力不写成已实现。

`deploy/api_smoke.py` 验证接口、真实 provider、规划启动和导出；`deploy/full_journey_acceptance.py` 进一步等待“新建请求→完整规划→最终校验→语义编辑→重排→导出”完成，作为主 Demo 的闭环验收。

### 复赛/决赛前必须补齐

1. 可复现交付包：Docker 启动、环境变量模板、离线样例、provider 配置说明、测试命令和脱敏运行证据。
2. 数据与第三方依赖披露：逐项说明来源、授权状态、处理方式、缓存/导出边界与替代方案。
3. 数据删除演示：现有行程级联硬删除会一并处理消息、规划状态、版本、任务、行程调用记录、附件元数据与安全目录内实体文件；Demo 中展示一次删除结果。
4. 安全边界展示：说明不接入车辆控制、不做自动驾驶决策，路线和天气需临近出发复核。
5. 运行证据：保存提交 SHA、环境、测试报告、关键 Skill 调用、失败分支和 Demo 视频。
6. 开放与复用说明：确定根目录开源许可证，说明 Skill Adapter、Schema 与场景模板如何被复用。

### 仅在部署方式触发时才需要

- 公网可写、多用户共同使用：再加入登录、资源级鉴权、租户隔离和更严格限流。
- 长期保存真实用户订单、位置或车辆数据：再加入更完整的隐私告知与数据主体请求流程。
- 对外承诺生产 SLA：再建设熔断、告警、容量压测和灾备。

这些都不是本地/受控参赛 Demo 的先决条件。

## 7. 可继续优化但不是参赛硬门槛

1. 把 `deploy/api_smoke.py` 输出保存成带提交 SHA、时间和 provider 状态的机器可读报告。
2. 在现有需求、续航和安全基线之上补真实车辆遥测与 10–20 条真实完整旅程，统计约束满足率、路线闭环率、来源覆盖率和自动修复成功率。
3. 继续扩展 E2E：已有规划页选择、三侧折叠、失败恢复、候选预览和导出门禁；还需覆盖历史批量删除、真实地图编辑与多轮云端确认。
4. 为 Skill Registry 增加调用预算、熔断和 provider 级延迟/失败率告警。
5. 对导出做快照或图像回归，检查重复图片、缺图、路线图失真和引用丢失。
6. 增加移动端、键盘操作、色彩对比度、弱网断线重连和 7–14 天长行程测试。
7. 地图标记合并、历史批量删除和完整编辑闭环仍需要更多单测与 E2E。

## 8. 明确无需为比赛强做的能力

- 真实车辆控制、自动驾驶决策、CAN 总线或车机硬件接入；手册明确不要求。
- 完整多租户 SaaS、企业 SSO、计费和高并发架构；本地/受控 Demo 可以成立。
- 自建向量知识库；当前实时检索增强已经满足可选路径。
- 全量语音、多摄像头或传感器能力；多模态是欢迎项而非必选。
- 每个第三方 provider 永远在线；比赛更看重失败能否解释和降级。
- 大规模真实用户数据；公开、模拟或示例数据被明确允许。

## 9. 建议评测指标

| 指标 | 建议门槛 |
| --- | --- |
| 必填约束提取准确率 | ≥ 95% |
| 跨城同名地点消歧成功率 | ≥ 95% |
| 相邻阶段连续率 / 往返闭环率 | 100% |
| 硬时间窗和活动冲突通过率 | 100% |
| 多日三餐/住宿覆盖率 | ≥ 95%，并说明途中餐例外 |
| 景点/餐饮/住宿来源覆盖率 | ≥ 90% |
| 自动修复后通过率 | ≥ 90% |
| 编辑失败不污染 canonical Trip | 100% |
| provider 故障可解释降级率 | 100% |
| P95 规划耗时和首个可见事件时间 | 按演示环境实测并披露 |
| 能耗 / 等效续航 MAPE | 模拟基线均 ≤ 12%；真实遥测单独披露 |
| 到达 SOC MAE | 模拟基线 ≤ 5 个百分点；真实遥测单独披露 |

这些指标需要由固定输入、期望约束和实际输出自动计算；仅凭截图不能替代评测报告。
