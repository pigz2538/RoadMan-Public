# RoadMan 下一轮实现计划（2026-08-03）

## 目标拆分

1. **候选检索**：`discover_tourism` 继续保留高德道路与 POI，同时明确调用 `flyai.poi` 获取景点和餐饮候选、`flyai.hotel` 获取住宿候选；每个候选保留图片、详情链接、评分、价格与来源，交给 POI Agent 去重和排序。
2. **规划体验**：详情页在初次规划、失败重试和聊天触发的整体重规划期间显示高斯模糊背景、旋转等待层和实时百分比；后台 SSE 事件仍按阶段/活动逐项注入，完成后再自然收尾。
3. **自然语言重规划**：编辑 Agent 返回 `replan`/`adjust` 意图时，由前端真正调用 planning start 接口，清空旧事件并重新连接/轮询，而不是只显示一条聊天回复。
4. **车型管理**：车型抽屉支持读取、新增、编辑、删除和设为当前车型；当前车型写入浏览器偏好，并在新建 Trip 时传递 `selected_vehicle_id`，让后端车辆/补能 Agent 使用真实配置。
5. **日期鲁棒性**：Requirement Agent 负责地点、人数、偏好和体验语义；离线结构化层只保护明确日期结构，覆盖 ISO/数字日期、今天/前天/后天、周末、周一至周日、下周天，以及英文 today/tomorrow/weekend/weekday。每轮预检都从原文刷新日期字段。

## 验收标准

- 规划事件中能看到 FlyAI 景点、餐饮、住宿调用和来源；FlyAI 不可用时明确降级，高德仍能提供候选。
- “换成两天行程”等整体修改会出现新的进度条和等待层，并最终刷新详情页。
- 车型可以在抽屉中保存并切换，刷新首页后当前选择仍保留；删除当前车型后自动选择剩余车型。
- `周一出发周五返回`、`后天/前天`、`周末`、`下周天`、`next Sunday` 等输入不会因日期字段缺失而卡住；日期倒序仍会明确提示用户。
- 后端测试、前端 TypeScript/Vite 构建均通过。
