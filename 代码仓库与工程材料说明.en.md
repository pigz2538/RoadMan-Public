## 1. Entry Points

RoadMan provides two entry modes: **Docker Compose (recommended, production-style)** and **local Conda (development/debugging)**.

| Entry | URL | Description |
| --- | --- | --- |
| Web workbench | `http://localhost:8080` | Single entry; Nginx serves the frontend and reverse-proxies `/api` and `/health` to the backend |
| Backend API docs (OpenAPI) | `http://localhost:8000/docs` | Auto-generated by FastAPI; contains all request/response contracts |
| Backend health check | `http://127.0.0.1:8000/health` | Returns `status`, `environment` and the registered Skill name list |
| Skill health & metrics | `http://127.0.0.1:8000/api/v1/skills/health`, `/calls`, `/metrics` | Per-capability config/degradation status and call statistics |
| Unified health check (via Nginx) | `http://127.0.0.1:8080/health` | Same-origin verification through the frontend entry |
| LAN demo | `http://<host-LAN-IP>:8080` | `frontend` binds all interfaces via `0.0.0.0:8080:80` |

> Compute & data entry: the backend API is only exposed on the host loopback `127.0.0.1:8000:8000` for local tools and Playwright; browser requests always go through the Nginx `/api/` reverse proxy rather than hitting the backend directly. `proxy_buffering off` ensures the SSE (`/planning/events`) event stream is not buffered.

### 2.2 Python Dependencies (`backend/requirements.txt`)

- **Backend core**: FastAPI (≥0.115), uvicorn, Pydantic 2 (≥2.10), pydantic-settings, SQLAlchemy 2.0 async, Alembic, aiosqlite (local SQLite), asyncpg (production PostgreSQL), redis, arq (worker), httpx, structlog, jsonschema, langgraph (≥1.0).
- **Document & export**: pypdf, python-docx, openpyxl, reportlab, python-pptx, Pillow.
- **Development & testing**: pytest, pytest-asyncio.

The backend image additionally installs Chinese fonts `fonts-noto-cjk` and `fonts-arphic-ukai` so PDF/long-image exports render Chinese correctly.

### 2.3 Node Dependencies

- Frontend: `frontend/package.json`, installed via `npm ci`, production build via `npm run build` (`vue-tsc -b && vite build`). Core stack: Vue 3.5, Vite 8, TypeScript 5.9, Pinia 3, Vue Router 4.5, TanStack Vue Query 5, AMap JSAPI loader, model-viewer.
- FlyAI CLI: `backend/node-requirements.txt` pins `@fly-ai/flyai-cli@1.0.16`. The Docker backend image installs this CLI globally from a `node:22-slim` stage and copies `node`, `flyai` and the `@fly-ai` module into the Python image for the `flyai.*` (train/flight/ferry/hotel/POI/search) Skill subprocess calls.

### 2.4 External Capabilities & Credentials

| Variable | Purpose | Notes |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | Cloud agents for requirement understanding, destination research, semantic edits, etc. | Required; default model `DEEPSEEK_MODEL=deepseek-v4-flash` |
| `DEEPSEEK_REASONING_EFFORT` | Reasoning depth | Default `max` (official DeepSeek values `low/high/max`) |
| `DEEPSEEK_THINKING` | Enable thinking mode | Default `true` |
| `DEEPSEEK_API_URL` | Chat Completions endpoint | Default `https://api.deepseek.com/chat/completions` |
| `AMAP_WEBSERVICE_KEY` | Geocoding, POI, real driving/walking/cycling/transit routes, traffic | Required; missing → those capabilities degrade |
| `FLYAI_API_KEY` | Travel search, lodging, dining supplement | Recommended |
| `OPENTRIPMAP_API_KEY` | International/open attraction data supplement | Optional |
| No extra variable | Bitefu primary vehicle catalog plus AutoSeeker, OpenEV Data, AppByte Fleet Catalog and CarNewsChina public supplements | Keyless; queried dynamically by vehicle request, retaining other sources or an explainable empty result on failure |
| `VITE_AMAP_JSAPI_KEY` / `VITE_AMAP_SECURITY_JS_CODE` | Real browser map | Injected at build time; frontend must be rebuilt after changes |
| `VITE_AMAP_SERVICE_HOST` | Same-origin proxy host for the AMap JS API loader | Optional |
| `ROADMAN_HTTP_PROXY` | Host proxy needed by containers to reach the internet | Docker Desktop: `http://host.docker.internal:<port>` |
| `CORS_ORIGINS` | Allowed cross-origin origins, comma-separated | Default `http://localhost:8080` |
| `POSTGRES_*` | Compose database account/database name | Override the default password in production; `POSTGRES_PASSWORD` defaults to `roadman_dev` |

> Authoritative key names and defaults: see [.env.example](.env.example) and `docker-compose.yml`. Missing non-required keys degrade the corresponding capability automatically (e.g. the frontend falls back to `MockRouteMap` without a browser map key) without affecting the main flow. `LOAD_LOCAL_SKILL_CREDENTIALS` controls whether local Skill credential files are read; set to `false` in Compose.

Home weather has no fixed-city default: after browser permission it requests Open-Meteo with the current coordinates and calls `amap.reverse_geocode` for a city/region label; a temporary location failure can only use the last coordinates stored in that browser, otherwise the weather card remains unavailable. Vehicle search queries the primary catalog first, then searches the public sources above in parallel for a missing or fuzzy trim; absent public fields stay empty and are recorded as missing or estimated.

## 3. Configuration Files

| File | Description |
| --- | --- |
| [.env.example](.env.example) | Template for all environment variables with defaults; copy to `.env` and inject real credentials |
| [docker-compose.yml](docker-compose.yml) | Defines the five services `postgres` / `redis` / `backend` / `worker` / `frontend` with dependency order, health checks, volumes and ports |
| [backend/Dockerfile](backend/Dockerfile) | Python 3.11 image; runs `alembic upgrade head` then starts uvicorn; installs the FlyAI CLI and Chinese fonts |
| [frontend/Dockerfile](frontend/Dockerfile) | Node 22 build stage (`npm ci` + `npm run build`) + Nginx hosting stage; injects `VITE_AMAP_*` at build time |
| `backend/app/core/config.py` | pydantic-settings `Settings`; holds all provider environment variables and defaults |
| `backend/alembic.ini` + `backend/alembic/` | Database migration config and migration scripts |
| `deploy/nginx/default.conf` | Reverse-proxies `/api/` and `/health` to `backend:8000`; disables buffering for SSE; SPA route fallback to `index.html` |

> Credential policy: backend keys are always written to the **untracked** root `.env` first and injected into containers on `docker compose up`; frontend `VITE_` variables are injected at build time. `.env`, `Skills/**/apikey.txt`, `secretkey.txt` and `apipkey.txt` are ignored by [.gitignore](.gitignore) and never enter git, SSE, logs or exports. Audit & metrics endpoints only return provider health/degradation status, latency and error codes — never keys, cookies or sensitive request-body fields.

## 5. Deployment

### 5.1 Docker Compose (Recommended)

```powershell
# 1. Prepare configuration
Copy-Item .env.example .env
# 2. Fill in at least DEEPSEEK_API_KEY and AMAP_WEBSERVICE_KEY in .env
# 3. Start (first build builds images and initializes the DB, takes a few minutes)
docker compose up -d --build
# 4. Verify
docker compose ps
python deploy/api_smoke.py
```

Service dependency order pulls up downstream services only after health passes: `backend` depends on `postgres` + `redis`; `worker` depends on `backend` + `postgres` + `redis`; `frontend` depends on `backend`. postgres/redis/backend all have healthchecks configured. The backend start command runs `alembic upgrade head` before uvicorn; backend and worker share the `UPLOAD_DIR=/app/data/uploads` volume and `FILE_RETENTION_DAYS`.

### 5.2 Backup & Restore

- Backup: `deploy/scripts/backup.ps1` uses `pg_dump --clean --if-exists` to export a timestamped SQL dump (default output `./backups`).
- Restore: `deploy/scripts/restore.ps1` uses `psql -v ON_ERROR_STOP=1`, overwrites the current database and requires explicit confirmation; run `docker compose stop backend worker` first to isolate writes, then restart and verify `/health` after restore.

### 5.3 Nginx & HTTPS

`deploy/nginx/default.conf` reverse-proxies `/api/` and `/health` to `backend:8000` with `proxy_buffering off` so SSE is never buffered; `/assets/` uses immutable long-term caching, all other SPA routes fall back to `index.html` with caching disabled. HTTPS and LAN access configuration: see [docs/operations.md](docs/operations.md).

### 5.4 Local Conda (Development)

```powershell
conda env create -f environment.yml
conda activate roadman
pip install -r requirements.txt
$env:PYTHONPATH = 'backend'
alembic -c backend/alembic.ini upgrade head
uvicorn app.main:app --reload --port 8000
```

Frontend in a separate terminal: `cd frontend; npm install; npm run dev`. Local defaults to SQLite; async planning depends on Redis and a worker — use `docker compose up -d postgres redis worker` to bring up only the dependency services.

## 6. Test Methodology & Runtime Evidence

### 6.1 Automated Verification System

| Layer | Entry | Coverage |
| --- | --- | --- |
| Backend unit & integration | `pytest backend/tests -q` | 14 test files, 136 test functions: API, planning graph, editing, adapters, export, travel, daily re-verification, DeepSeek provider, Skill Registry |
| Frontend state tests & build | `npm run test` / `npm run build` | Planning event dedup, progressive display, type check and production build |
| Frontend E2E | `npm run test:e2e` | Playwright: `roadman.spec.ts`, `planning-agent.spec.ts`, `firefox-compat.spec.ts` |
| API smoke | `python deploy/api_smoke.py` | Health, CRUD, external capabilities, planning start, export gate on running containers |
| Full-journey acceptance | `python deploy/full_journey_acceptance.py` | Create → complete → semantic edit → replan → five-format export |
| Edit-replan acceptance | `python deploy/edit_replan_acceptance.py` | Patch preview, confirm, apply, replan and failure-without-contaminating-the-official-trip |
| Requirement understanding evals | `python evaluation/run_evals.py` | Constraint extraction & structural validation across 12 scenarios |
| Range accuracy | `python evaluation/range_accuracy.py` | Energy MAPE, equivalent-range MAPE, arrival-SOC MAE |
| Safety & degradation | `python evaluation/safety_scenarios.py` | Low battery, severe weather, insufficient charging, missing vehicle info, external service errors |

### 6.2 Produced Runtime Evidence

| Evidence | Value (baseline) |
| --- | --- |
| Requirement understanding evals | 12 scenarios |
| Range accuracy (simulated replay) | 12 samples: energy MAPE **8.442%**, equivalent-range MAPE **9.302%**, arrival-SOC MAE **2.799 pp** (thresholds 12% / 12% / 5pp, all pass) |
| Safety & degradation scenarios | 5/5 matched expectations; task completion rate **100%**, route executability rate **80%** (honestly marked not-yet-executable when charging stops only have estimated locations) |

> The range baseline uses `simulation_sensor_replay` data, which only proves the error-computation and SOC-continuity chain is reproducible — it does **not** constitute a real-vehicle range promise; when real road-test data is onboarded, keep the same fields and change `data_kind` to `vehicle_telemetry`, and disclose the two separately. In safety scenarios, `route_executability_rate` ≠ task completion rate: when charging stops only have estimated locations, the system completes the "honest degradation" task, but the route is explicitly marked not-yet-executable — it never masks risk with a fake 100%.

### 6.3 Runtime Evidence & Reproducibility

Runtime evidence includes backend tests, API smoke, requirement evals, full-journey acceptance and call audits, all retaining execution date, Git SHA and commands while hiding keys and personal paths. Requests and traces are propagated via `X-Request-ID` and `X-Trace-ID`; Skill calls are recorded through the Skill Registry with provider, latency, success/cache, error code and source summary — never keys or raw model output. OpenAPI at `/docs`; skill health and metrics at `/api/v1/skills/health`, `/calls`, `/metrics`.

## 7. Facts Underlying External APIs (Official Documentation)

| Capability | Fact Basis | Official Docs |
| --- | --- | --- |
| DeepSeek Chat Completions | `POST /chat/completions`, OpenAI-compatible; `base_url=https://api.deepseek.com`; model `deepseek-v4-flash`; thinking mode `{"thinking":{"type":"enabled"}}` (default enabled, default effort high); `reasoning_effort=low/high/max` (`medium`/`xhigh` map to `high`); JSON output `{"type":"json_object"}` (the model must be explicitly instructed in the message to output JSON, otherwise blank streams or `finish_reason=length` truncation may occur); thinking mode ignores `temperature`/`top_p`/`presence_penalty`/`frequency_penalty`; chain-of-thought is returned via `reasoning_content`, which RoadMan never persists or logs | [api-docs.deepseek.com](https://api-docs.deepseek.com/api/create-chat-completion/) |
| AMap | WebService REST (`restapi.amap.com`) geocoding/POI/driving/walking/cycling/transit/traffic; browser maps use JSAPI v2 + `key` + `securityJsCode` | [lbs.amap.com](https://lbs.amap.com/) |
| Open-Meteo | `GET https://api.open-meteo.com/v1/forecast`, params `latitude/longitude` (WGS84), `hourly`, `daily`, `forecast_days` (default 7, max 16), `timezone`, etc.; no key needed by default, `apikey` with `customer-` prefix only for commercial use; data from multiple national weather services (DWD, NOAA, ECMWF, Météo-France, JMA, KMA, CMA, etc.); non-commercial free, commercial/self-hosted per their license | [open-meteo.com](https://open-meteo.com/en/docs) |
| OpenTripMap | `GET api.opentripmap.org/0.1/en/places/radius`; open places based on OpenStreetMap (ODbL) and Wikidata/Wikipedia; source & attribution must be retained | [opentripmap.io](https://opentripmap.io/) |
| Vehicle catalog | Primary `tool.bitefu.net/car` catalog; when a concrete trim is absent, dynamically queries AutoSeeker JSON (CC BY 4.0), OpenEV Data (CC BY-SA 4.0), AppByte Fleet Catalog REST and public CarNewsChina model pages. Only source-provided identity/spec fields are used; absent values stay empty | [Primary](https://tool.bitefu.net/car/), [AutoSeeker](https://autoseeker.eu/data/models.json), [OpenEV Data](https://gaia-charge.github.io/evdb/v1/vehicles.json), [AppByte](https://fleetcatalog.disturbingbyte.pt), [CarNewsChina](https://data.carnewschina.com/suggest) |
| LangGraph | Python `langgraph>=1.0`; `StateGraph`, `add_node`, `add_edge`, `add_conditional_edges`, `compile` (RoadMan uses a 22-node state machine), checkpointer persistence supported | [langchain-ai.github.io/langgraph](https://langchain-ai.github.io/langgraph/) |

> Note: the API facts above were taken from the corresponding official documentation at the time of writing; the provider status reachable at runtime is governed by `/api/v1/skills/health`. The JSON output convention used by the DeepSeek API is explicitly demanded from the model inside RoadMan's prompts, matching the official "JSON Output requires explicit in-message instruction" requirement.
