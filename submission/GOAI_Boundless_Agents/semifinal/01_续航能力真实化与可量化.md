# 优化方向一：续航能力真实化与可量化

## 1. 对评委意见的处理

旧逻辑在补能后把 SOC 恢复到固定值，无法反映桩功率、补能时长和车辆受电能力。现在每个路线阶段都保留起始 SOC、预计消耗、补能前 SOC、补入量、补能后 SOC 和到达 SOC。后一阶段从前一阶段的到达值继续计算。

补能数据按以下顺序使用：

1. 有实际补入电量或加油量时，采用 `actual_energy_added_kwh` 或 `actual_fuel_added_liters`。
2. 没有实测值但有桩功率和时长时，按有效功率、时长和 90% 效率估算。有效功率取桩功率与车辆最大受电功率中较小的值。
3. 功率缺失时，使用车辆上限与 60kW 中较小的值，并写入 `CHARGING_POWER_ESTIMATED`。
4. 补能服务没有返回可用地点时，只给出路线上的估算检查位置。该路线标为需要人工确认。

## 2. 连续 SOC 计算

纯电车型单阶段的预计能耗为：

```text
E_use = distance_km x consumption_kWh_per_100km / 100 x route_factor
SOC_used = E_use / battery_kWh x 100
```

路线工具返回的累计爬升达到阈值时，`route_factor` 取 1.12。地点名称中出现“山”或“峰”不会触发地形系数。燃油车按额定续航和实际油耗计算消耗，不套用电池模型。

补能点有坐标时，系统在路线 geometry 上寻找最近位置，并分别计算补能前后的路段消耗。缺少坐标时按阶段中点估算，同时提示位置不确定。

```text
SOC_before = clamp(SOC_start - SOC_used_before_stop, 0, 100)
SOC_after  = clamp(SOC_before + energy_added / battery_kWh x 100, 0, 100)
SOC_arrive = clamp(SOC_after - SOC_used_after_stop, 0, 100)
next_stage.SOC_start = current_stage.SOC_arrive
```

长途驾驶拆成多段后，总能耗保持不变。只有发生补能的分段边界保存补能字段，其余分段直接传递剩余 SOC。

| `calculation_basis` | 数据依据 | 性质 |
|---|---|---|
| `measured_energy` | 服务或车辆记录返回的实际 kWh/L | 实测 |
| `charger_power` | 桩功率、车辆受电上限、时长和效率 | 估算 |
| `conservative_fallback` | 功率缺失时采用不超过 60kW 的保守值 | 估算 |
| `fuel_service_estimate` | 有加油服务点但加油量未知 | 估算 |

## 3. 异常输入怎么处理

| 输入 | 处理结果 |
|---|---|
| 一次上报 500kWh | 按电池剩余空间封顶，SOC 不超过 100% |
| 桩功率 350kW，车辆上限 90kW | 按 90kW 计算 |
| 功率为 0、补能量为负数、时长无法解析 | 忽略坏值，转入保守估算并告警 |
| 燃油车实际补入 18L | 按油箱容量更新剩余比例 |
| 当前 SOC 为 180% | 限制为 100%，记录归一化告警 |
| 电池容量或能耗参数非法 | 使用保守默认值，并公开说明数据已降级 |
| 长途驾驶拆段 | 检查每段首尾 SOC 和总能耗 |
| 充电服务没有结果 | 插入估算检查点，路线状态改为需确认 |

这些回归位于 `backend/tests/test_deep_drive.py` 和 `evaluation/test_safety_scenarios.py`。续航专项测试当前为 22/22 通过。

## 4. 预测值与观测值

12 条基线样本覆盖常温平路、高速、城市低速、山路、低温、高温、降水、拥堵、满载、下坡回收和长途混合路况。

| 指标 | 当前结果 | 预设阈值 | 判断 |
|---|---:|---:|---|
| 能耗 MAPE | 8.442% | <= 12% | 通过 |
| 能耗 MAE | 2.295kWh | 信息项 | 记录 |
| 能耗 RMSE | 2.605kWh | 信息项 | 记录 |
| 能耗偏差 | -1.962kWh | 信息项 | 整体偏乐观 |
| 能耗 P95 绝对百分比误差 | 15.707% | 信息项 | 尾部误差仍明显 |
| 等效续航 MAPE | 9.302% | <= 12% | 通过 |
| 到达 SOC MAE | 2.799pp | <= 5pp | 通过 |
| 到达 SOC P95 误差 | 5.287pp | 信息项 | 用于检查安全余量 |

低温样本是误差较大的项目之一。固定基础能耗还不能充分描述电池温度、热管理和空调负荷，这项偏差会在答辩中如实说明。

## 5. 实车数据采集方案

仓库目前没有可供审计的真实车辆遥测集，因此不能把上面的指标称为实测结果。下一轮计划采集至少 30 个有效路段：

1. 记录车型、电池可用容量、起止 SOC、里程、平均速度、气温、降水、载荷、累计爬升、空调状态和实际补能量。
2. 路段中途发生补能时，拆成前后两个样本，并记录桩侧实际电量。
3. 仪表 SOC 在车辆静置后读取；同一车型覆盖常温、低温、高速、拥堵和山路。
4. 不采集车牌、VIN、精确家庭地址和乘员身份。发布评测集前删除或网格化起终点坐标。
5. `data_kind` 设为 `real_vehicle_telemetry`，并保留采集日期、仪表来源和脱敏说明。
6. 按路线或日期拆分校准集与评测集，避免在同一批样本上调参和报分。

```powershell
python evaluation/range_accuracy.py `
  --input evaluation/range_observations.real.local.json `
  --output evaluation/results/range-accuracy-real.json `
  --require-real
```

输入仍为模拟回放时，命令会返回退出码 2 和 `REFUSED`。

## 6. 现场核对

在新能源长途行程中打开任一阶段卡，可以依次看到补能前 SOC、功率、时长、补入量和到达 SOC。再运行 `python evaluation/range_accuracy.py`，评测看板会读取同一份 JSON。演示时需要明确说明样本类型，并保留低温尾部误差。
