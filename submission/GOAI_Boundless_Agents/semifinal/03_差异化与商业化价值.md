# 优化方向三：差异化与商业化价值

## 1. 先服务哪些用户

RoadMan 面向需要安排多日行程、车辆补能或反复修改计划的人。这些任务通常要在地图、攻略、天气、酒店和备忘录之间来回核对。

| 用户 | 常见任务 | 现有流程的麻烦 |
|---|---|---|
| 新能源自驾情侣或家庭 | 多日路线、舒适作息、补能余量、稳定住宿 | 单段路线容易查，每天的活动和补能仍要手工拼接 |
| 跨城交通加本地游用户 | 比较飞机、高铁或火车，衔接站场、酒店和景点 | 班次、景点、餐饮和住宿分散在不同入口 |
| 经常调整计划的深度旅行者 | 增删地点、改变停留时间、换酒店后重排 | 局部收藏很方便，跨日时间和路线仍需重新计算 |

RoadMan 处理的是多日行程的编排和校验：它把用户要求、来源、交通、时间、能耗、住宿、餐饮、风险和修改记录放在同一个 Trip 中。

## 2. 与高德、马蜂窝的公开定位比较

下表只比较各产品公开页面中明确介绍的能力，不推断其未公开功能。

| 维度 | 高德地图公开重点 | 马蜂窝公开重点 | RoadMan 当前做法 |
|---|---|---|---|
| 路线 | 实时交通、驾车与公共交通路线、停车和充电信息 | 目的地与旅行产品内容 | 调用在线地图查询路线，另外维护跨日时间、住宿、补能和返程状态 |
| 目的地资料 | 地点搜索、周边生活和商家信息 | 攻略、游记、主题灵感、当地活动和商品 | 多源查询后合并候选，采用项保留来源、时间和适配理由 |
| 多日计划 | 可分享路线与路书 | 行程灵感和自由行内容 | 同时校验三餐、住宿、活动、休息、补能和返程 |
| 新能源 | 充电设施与路线相关能力 | 公开页面未列为主要方向 | 连续计算 SOC，区分实测补能、功率估算和服务中断 |
| 修改 | 编辑路线点 | 选择内容和商品 | 修改先预览，确认后重算路线、时间、SOC 和住宿 |
| 追溯 | 以实时地图服务为主 | 以内容和交易服务为主 | 保存采用候选、风险、工具调用及降级状态 |

公开资料：

- 高德地图：[产品页](https://mobile.amap.com/cn/Index.aspx)、[路线规划帮助](https://www.amap.com/ssr/doc/route-plan)、[开放平台路线规划](https://lbs.amap.com/product/path)
- 马蜂窝：[目的地页](https://m.mafengwo.cn/mdd/)、[首页](https://www.mafengwo.cn/index.php)、[当地玩乐](https://m.mafengwo.cn/localdeals/)

RoadMan 使用地图完成路线计算，也会使用攻略和开放地点资料。它的工作从这些数据之后开始：整理每天的先后顺序、住宿锚点、补能余量和修改影响，最后交给用户确认。实时导航仍由地图或车机完成。

## 3. 四项具体差异

### 3.1 多日路书按约束排程

```mermaid
flowchart LR
    A[自然语言需求] --> B[地点/日期/同行人/舒适度]
    B --> C[目的地研究与候选]
    C --> D[每日地理主轴]
    D --> E[路线/三餐/酒店/活动]
    E --> F[补能/休息/天气/预约]
    F --> G[每日复核与修复]
    G --> H[可执行路书]
```

系统先确定目的地范围，再检索公开来源。同一景区的入口、停车场和游客中心会合并；道路、旅行社、企业和普通服务设施不会被排成三小时景点。通过实体检查的候选还要参考研究证据、用户偏好和相邻转场距离，只有当日路线经过的地点才进入活动卡。

### 3.2 补能余量有计算依据

阶段卡显示起始 SOC、预计消耗、补能前 SOC、补入量、功率、时长、补能后 SOC 和到达 SOC。有实际补能量就采用实际值，缺失时才估算。估算位置会标为待确认。车型主目录没有具体版本时，系统会查询多个公开车型数据源，并保留参数来源和缺失标记。

### 3.3 语义判断与硬校验分开

智能体处理“情侣出行想轻松一点”“不要每天换酒店”“三天都待在九宫山”等表达。路线工具和校验器检查坐标、耗时、阶段连续、SOC 和返程。模型可以提出修改方案，不能绕过安全规则。

### 3.4 修改会改变正式行程状态

删除的地点进入排除集合，后续重排不会自动加回。地图选点和自然语言修改先生成 PlanPatch 预览，用户确认后才写入正式 Trip。重排会更新路线、时间、住宿和能耗，并再次运行校验；失败时保留原版本。

## 4. 如何量化用户价值

当前没有足够样本证明节省金额或商业收入，因此只列出可采集指标。

| 要验证的问题 | 指标 | 采集位置 |
|---|---|---|
| 规划是否更快 | 从输入到首个可执行方案的时间 | Job 开始与完成时间 |
| 是否减少手工拼接 | 完成任务时跳转外部应用的次数 | 可用性测试观察 |
| 行程是否完整 | 三餐、住宿、返程、休息、补能覆盖率 | 校验器结果 |
| 修改是否可靠 | 预览确认后一次重排通过率 | PlanPatch 与 verification 日志 |
| 不确定信息是否说清 | 估算和未知字段的正确标记比例 | warning 与 source 审计 |
| 推理成本是否可控 | 单条行程 Token、工具次数和 P95 时延 | `/api/v1/ops/metrics` |

建议邀请 8 到 12 名目标用户，分别用“地图 + 攻略 + 备忘录”和 RoadMan 完成同一任务，比较用时、遗漏项、修改次数和主观信心。样本较小时报告原始分布和描述性统计，不做显著性推断。

## 5. 收费和合作方式

### 5.1 B2C 订阅

免费层可提供基础多日规划、地图浏览和单次导出。订阅层可增加多车辆档案、进阶能耗模型、历史版本、协作编辑和出发前风险复核。付费不会改变安全校验结论，也不以出售精确轨迹获利。

### 5.2 车企和租车服务

可向车企 App 或租车服务输出“车型参数 + 多日路书 + 补能余量”的结构化结果。接口只提供规划数据，不接入车辆控制，也不承担自动驾驶决策。

营地、民宿和目的地机构可以提供候选资料，但赞助内容必须单独标注，不能混进自然排序。

### 5.3 企业差旅与团建

把多人偏好、固定参观点、班次、酒店和时间窗作为约束，输出待确认路线和风险清单。该方向仍需组织权限、审批、发票或预算处理及多租户隔离，当前 Demo 没有把这些能力写成已完成事项。

## 6. 长期积累来自哪里

可持续积累的数据包括车型与路况下的误差校准、校验失败及修复结果、用户确认过的修改意图，以及不同 provider 的稳定性记录。统一领域模型和 Skill 契约让这些数据可以在更换模型或服务商后继续使用。

这些数据只能在用户授权、最小化收集和可删除的前提下使用。当前 Demo 没有账号级长期画像。

## 7. 答辩表达

一句话说明：

> RoadMan 把目的地资料、跨城交通、每日安排、车辆续航和用户修改整理成一份经过校验的多日路书，实时导航仍交给地图或车机。

商业价值部分可现场展示一条新能源多日行程和一次换酒店操作，再打开评测页核对结果。最后说明 B2C 订阅与车企、租车接口两条路径，以及不接车辆控制的责任范围。
