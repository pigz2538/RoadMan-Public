# 这份清单怎么用

这不是“把答案写在题目里”的考试题，而是一组可以直接复制到 RoadMan 首页输入框的真实用户说法。每条都尽量像人在手机上随手发出的消息：有的说得完整，有的只给大概时间，有的临时补充偏好，有的会让智能体先追问再继续。不要把下面的提示词拼接到一起；每条都从一个新行程开始。

展示时建议按 `01 → 02 → 03 → 04 → 10` 的顺序，先让观众看到自然语言理解和跨城规划，再展示特殊活动检索、目的地研究和修改闭环。其余案例可根据现场时间选取。

## 成功的定义

“成功”不等于接口返回 200，而是用户能在页面上看到一条可解释、可修改、可复核的行程：

- 目的地、出发地、同行人数和偏好被正确理解；不把餐馆、公司或活动名称误当成目的地。
- 跨城交通、机场/车站接驳和市内移动有连续的起点与终点；有返程时最后能回到用户说的返程地点，允许地图坐标在合理的近距离内合并。
- 每天有合适的早餐、午餐、晚餐、休息和住宿，不用一整天只安排一段交通或把晚餐塞进移动时间。
- 景点、餐厅、酒店和特殊活动有来源、图片、开放/预约提示；不确定的信息显示为“出发前复核”，而不是伪装成确定事实。
- 规划校验发现问题时，智能体自动调整候选、时段或交通方式并再次复核；只有确实需要用户选择时才提问。
- 用户修改或地图选点后，页面先展示修改预览，用户确认后统一重排路线和时间；失败时保留原行程，不覆盖已确认版本。
- 导出内容与详情页使用同一份已完成快照，地图、路线、图片和来源一致。

## 截图规则

每条案例成功后立刻截图，不要等所有案例跑完再凭记忆补图。截图至少包含：页面标题、地图或阶段卡片、右侧协作消息/来源卡片中的一个。规划尚未完成时不要截导出按钮；若案例需要追问，截图应包含问题和用户回答后的最终确认状态。

截图目录统一使用：

```text
artifacts/showcase/prompt-screens/01-main-cross-city.png
artifacts/showcase/prompt-screens/02-family-ev.png
...
artifacts/showcase/edit-screens/E01-delete-overload.png
...
```

截图不要包含 API Key、个人精确住址、账号、Cookie 或未脱敏的电话号码。地图加载完成后再截，浏览器窗口建议使用 1440×900；详情页截图应把当前阶段卡片、路线和 Agent 行程助理一起放入画面。截图成功后在本文对应条目的“截图”行填入相对路径和运行日期。

# 10 条自然输入：展示需求理解与完整规划

## 01｜下班后去北京，舒适地看一圈

**直接输入：**

```text
我和对象下周五下班后从武汉去北京，周日晚上回武汉，想看点真正值得看的地方，节奏舒服一点，交通高铁、飞机或者卧铺你帮我比较，别让我刚下车就去景点，住的地方也别每天换。
```

**展示重点：**相对日期、情侣人数、跨城交通比较、抵达缓冲、北京代表性景点和同一酒店复用。重点观察“北京”不会被理解成武汉的北京烤鸭店，市内阶段也不应凌晨出发。

**通过标准：**给出交通方案及选择依据；抵达后先办理入住/休息，再安排白天景点；每天有吃饭和休息；周日晚间回到武汉；不确定的预约和班次有来源提示。

**截图：**`artifacts/showcase/prompt-screens/01-main-cross-city.png`

## 02｜带父母去黄山，别把行程排成拉练

**直接输入：**

```text
过几天想带爸妈从上海去黄山住两晚再回来，老人走不了太多坡，我自己开一辆纯电 SUV，电量大概八成。想住得舒服，路上每隔一阵子能休息一下，山上如果不适合就给我换成轻松一点的景点。
```

**展示重点：**车辆档案、纯电续航、充电站/服务区、老人和爬坡偏好、海拔与天气适配、酒店复用。

**通过标准：**补能点来自可追溯数据；连续驾驶和步行不超舒适上限；老人不被安排高强度路线；充电、三餐、入住、返程都有时间；景点因天气或开放状态调整时给出理由。

**截图：**`artifacts/showcase/prompt-screens/02-family-ev.png`

## 03｜暑假找一个真的适合看流星的晚上

**直接输入：**

```text
暑假想和对象从武汉自驾去九宫山看英仙座流星雨，最多三天，不想为了赶路半夜开很久。你先查今年什么时候最适合看、月亮会不会太亮，再按天气和山里的情况安排观星、吃饭、睡觉，白天别排得太满。
```

**展示重点：**特殊天象研究、权威来源和时间窗、活动与目的地分离、夜间安全、山路驾驶、云量/月相与返程安排。

**通过标准：**智能体自行检索极大期、月相和可见窗口，并把来源/时区/不确定性写清楚；“九宫山”是目的地，“英仙座流星雨”是活动，不生成一个奇怪的合成景点；观星前后有餐饮、住宿和休息，避免观星结束后长途驾驶。

**截图：**`artifacts/showcase/prompt-screens/03-perseids.png`

## 04｜南京别只围着酒店附近转

**直接输入：**

```text
我想在南京玩五天，两个人，第一次去，想把秦淮河、明城墙、大报恩寺、中山陵、明孝陵、紫金山和南京的大学都逛到，也想吃几顿当地有代表性的东西。请先帮我看看哪些是南京真正值得去的，再按片区排，别每天拖着行李换酒店。
```

**展示重点：**目的地研究、著名景点覆盖、片区聚类、景点预约/开放时间、酒店作为稳定锚点、餐厅多样性。

**通过标准：**先给出候选和来源，再按秦淮河—城南、钟山—紫金山等片区安排；南京大学/东南大学等受限地点标明参观边界；上午/下午/晚上有合理节奏；五天不是只排中午一段路。

**截图：**`artifacts/showcase/prompt-screens/04-nanjing-research.png`

## 05｜带车上岛，先把船和车能不能上岛查清楚

**直接输入：**

```text
国庆想和对象从北海去涠洲岛，顺便在北海逛逛，玩几天再回北海。船票、车辆上岛、天气和岛上的住宿我都不熟，你先查清楚哪些能确定、哪些得提前订；如果车不能上岛，就把车留在港口，岛上用合适的接驳，别硬画一条海上的路。
```

**展示重点：**跨海交通、船班/车辆限制、天气风险、港口接驳、岛上交通、住宿复用与不确定性。

**通过标准：**不会把海口和涠洲岛用直线驾车连接；车能否上岛有来源；船班不可用时给出替代方案并说明取舍；港口—住宿—景点接驳连续，返程保留缓冲。

**截图：**`artifacts/showcase/prompt-screens/05-ferry-island.png`

## 06｜北京周末，别给我凌晨三点的景点

**直接输入：**

```text
这个周五晚上从武汉出发去北京，周日晚上八点前得回来，和对象一起，想看天安门、故宫一带和一两个博物馆。高铁、飞机、卧铺都可以，主要看哪个更舒服，到了以后先睡够，别把车站时间当成景点时间。
```

**展示重点：**跨城交通方案、到达时间语义、景点开放/预约、夜间作息、返程站场缓冲、市内公共交通。

**通过标准：**不安排凌晨参观；到达后先入住/休息；预约景点给出预约风险；返程时间包含到站和安检缓冲；路线卡片的起终点连续。

**截图：**`artifacts/showcase/prompt-screens/06-beijing-weekend.png`

## 07｜带老人去神农架，天气不合适就换方案

**直接输入：**

```text
想趁凉快带爸妈去神农架三天，从武汉出发再回武汉。我们喜欢自然风景，但老人怕热、怕长坡，也不想一天跑很多地方。你看当天的天气、海拔和开放情况安排，能坐接驳就别让我们一直走，三餐和午休都留出来。
```

**展示重点：**季节/天气/海拔适配、老人强度、景区接驳、午休、住宿复用和自然景观偏好。

**通过标准：**每个景点分别判断适配，不使用“某月一律禁止”的硬编码清单；恶劣天气有替代活动；步行强度和爬升可解释；餐饮、休息、返程完整。

**截图：**`artifacts/showcase/prompt-screens/07-shennongjia-family.png`

## 08｜不租车逛西湖，雨天也要有备选

**直接输入：**

```text
下个月找个周末去杭州，我不租车，住在杭州东站附近但不想每天都回车站。西湖、灵隐寺和几处适合慢慢走的地方想看看，地铁公交、骑行和短距离步行你帮我搭配，遇到下雨给我留室内选择，也算算每天大概走多少路。
```

**展示重点：**公共交通优先、骑行/步行切换、总爬升与单段步行、雨天备选、预约和酒店片区。

**通过标准：**不把自驾混进市内阶段；每段显示交通方式、距离、时长和步行负担；雨天备选来源清楚；返程回杭州东站并留足时间。

**截图：**`artifacts/showcase/prompt-screens/08-hangzhou-transit.png`

## 09｜成都出差顺便吃好、玩好，但别全是网红店

**直接输入：**

```text
我下周要去成都办几天事，白天有一两段固定工作，晚上和空出来的半天想吃点靠谱的川菜、火锅和小吃，再安排宽窄巷子、武侯祠或者熊猫基地里合适的几个。预算正常，餐厅不要每天重复，也别为了打卡把路绕得太远。
```

**展示重点：**固定工作时段保护、餐饮检索与去重、景点代表性、片区路线、预约/营业时间和舒适节奏。

**通过标准：**工作地点和旅游目的地不混淆；餐厅有地址、营业时间、评分/来源；午晚餐不与工作或移动重叠；景点数量与可用时间匹配；没有把“成都的某公司/餐厅”误当成城市目的地。

**截图：**`artifacts/showcase/prompt-screens/09-chengdu-business.png`

## 10｜有几个必须去的工作地点，其他交给你安排

**直接输入：**

```text
月底要从武汉去成都，先去麓湖 CPI，再去成都航天博目电子科技有限公司和中国电子科技集团第十研究所，办完事情后想留一点时间看看成都，最后回武汉。那几个地方是必须到的，地址和是否能进先查清楚，别拿附近一个景点替代；其余景点、吃饭、酒店和市内交通你按顺路安排就行。
```

**展示重点：**必达地点保护、企业地址核验、工作时段、机场/车站接驳、旅游候选、自然语言“其余交给你”的任务拆解。

**通过标准：**三个必达地点都保留并给出地址/访问边界；若无法公开核实，明确要求人工确认，不静默替换；工作与旅游时间不冲突；机场/车站—酒店—必达地点—返程连续；其余候选按片区和可用时间筛选。

# 10 条自然修改：展示“编辑—预览—确认—统一重排”

下面的消息都在已有规划详情页中发送，不要直接改数据库。每条修改都应先出现可读的修改预览；点击“确认应用”后，再点击页面提供的“重新规划路线/统一重排”。如果新安排不可行，保留原行程并解释原因。

## E01｜这天排太满，删掉最不值得的一站

```text
第二天看起来有点赶，把下午最远、评价一般的那个景点去掉吧，保留必去的，午饭和回酒店的时间别被吃掉。
```

**检查：**删除点不再出现在活动、地图和路线；其他卡片自动补齐时间；三餐/住宿不丢失。截图：`artifacts/showcase/edit-screens/E01-delete-overload.png`

## E02｜在地图上加一家晚餐

```text
我在地图上点了酒店附近那家评价不错的本地菜，想放到今天晚饭，离得太远就换附近同类型的，不要为了它改掉必去景点。
```

**检查：**地图选点进入候选池，餐饮卡出现来源和营业时间，路线与晚餐时段一起重排。截图：`artifacts/showcase/edit-screens/E02-map-add-dinner.png`

## E03｜换酒店，但不要让后面的路全翻掉

这家酒店房间不太合适，换成刚才候选里那家有独立卫浴、离景区近一点的，能少换酒店就少换，其他安排尽量保持。
```

**检查：**生成替换预览，住宿成为后续路线锚点，活动不被静默删除；确认后重新计算接驳。截图：`artifacts/showcase/edit-screens/E03-replace-hotel.png`

## E04｜市内既然开车，就别给我排公交

这几天我会一直开车，市区这些短途不用公交了，按停车方便和少绕路的方式重排，长途休息和补能别删。

**检查：**只改变允许的市内交通方式；停车/步行接驳有说明；长途补能和休息仍在。截图：`artifacts/showcase/edit-screens/E04-city-driving.png`

**检查：**停留时长增加、被删点有补丁、后续交通和晚餐顺移且不冲突。截图：`artifacts/showcase/edit-screens/E05-extend-stay.png`

今晚下雨的话不想逛户外，把夜游换成离酒店近的博物馆或茶馆，先帮我搜几个能营业到晚上的选项，我选一个再改正式行程。
```

**检查：**先返回候选和来源，不直接覆盖原行程；用户选定后生成替换预览，再统一重排。截图：`artifacts/showcase/edit-screens/E06-rainy-evening.png`

## E07｜加一个真实的充电休息点

第二天那段连续开车太久了，在中间找个有卫生间和吃饭地方的充电站停一下，哪怕晚到一点也比硬撑好。
```

**检查：**补能点与路线相交，新增休息/用餐时间，抵达时间联动更新；找不到可靠点时自动换方案而不是只报错。截图：`artifacts/showcase/edit-screens/E07-charge-rest.png`

**检查：**重新检索班次/航班并比较方案，保护返程截止时间；只在确认后替换正式路线。截图：`artifacts/showcase/edit-screens/E08-return-mode.png`

```

**检查：**只影响指定日期，必达点和其他日期不变；时间线、接驳、天气和地图同步更新；成功后导出快照可追溯。截图：`artifacts/showcase/edit-screens/E10-day-reorder.png`

# 运行与记录模板

## 单条主案例

1. 清空首页旧输入，粘贴提示词。
2. 等待需求理解卡片；如果智能体需要澄清，按真实用户方式回答，不替它补答案。
3. 点击确认后进入详情页，等待地图、阶段卡、餐饮/住宿卡和右侧协作消息稳定出现。
4. 检查上方“成功的定义”，保存对应截图。
5. 规划完成并通过校验后，任选 HTML/PDF/PPTX/长图导出一份；导出文件必须来自同一完成快照。

## 单条编辑案例

1. 从一个已完成行程开始，执行一条编辑消息或一次地图选点。
2. 截修改预览，确认应用，再点击统一重排。
3. 等待路线、时间线、卡片和地图全部更新，确认旧点/新点状态符合消息。
4. 保存对应截图；如重排失败，确认正式行程仍是修改前版本，并把失败原因记录下来。
